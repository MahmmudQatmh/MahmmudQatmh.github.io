BlueSim: multi-robot simulator in Unreal Engine 5

A photorealistic simulator with a surface boat, a drone and a ground rover, all controlled over ROS 2 through rclUE. Open source.

Multi-robot experiment: a Python ROS 2 node commands all three robots and shows their camera feeds.

Why I built it

Testing a new controller on a real boat costs a field day and carries risk. BlueSim lets the lab test perception and control on a surface boat, a drone and a ground rover in one shared world first, and then move the same ROS 2 code to hardware.

How it fits together

  1. Unreal Engine 5.4.4Physics-based motion for boat, drone and rover, with onboard cameras (640×360, 90° FOV).
  2. rclUE bridgeC++ publishers and subscribers inside the simulator.
  3. ROS 2 topics/camera_BlueBoat, /cmd_BlueBoat_vel, and pan/tilt camera control.
  4. Python nodesAutonomy, experiments and camera monitoring send Twist commands back.

Engineering choices

  • Robot physics is separate from the command source, so the same robot runs from the keyboard or from ROS 2 code without changes.
  • Standard ROS 2 messages (Twist, Image), so lab code moves to the real BlueBoat.
  • Built-in experiment for camera resolution against publish rate (5–30 Hz), to find bandwidth limits before field tests.
  • Floating buoys and a 2D LiDAR now support my thesis on USV collision avoidance.
